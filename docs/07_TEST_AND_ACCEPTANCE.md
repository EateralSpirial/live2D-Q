# 07｜测试、性能基准与验收标准

本文用于防止“功能看起来能动，但无法长期直播”。所有 P0 验收项通过后，才可把版本标记为 MVP 或发布候选。

## 1. 测试层级

| 层级 | 工具建议 | 目标 |
|---|---|---|
| 单元测试 | Vitest / pytest | 平滑、状态机、协议、资产规则 |
| 组件测试 | React Testing Library / pytest | UI 模块、配置、服务适配器 |
| 协议测试 | TS + Python golden fixtures | 双语言消息一致性 |
| 浏览器端到端 | Playwright | 麦克风模拟、控制页、overlay、重连 |
| 渲染回归 | Playwright screenshot + alpha 读取 | 透明、draw order、表情、口型 |
| 音频回归 | 固定 WAV 测试向量 | 视素、VAD、ASR、情绪稳定性 |
| OBS 手工测试 | OBS Studio | Browser Source、Alpha、切场景、同步 |
| 稳定性 | 脚本化 soak test | 30/120 分钟内存、FPS、重连 |

## 2. 测试数据规则

- 固定 WAV 测试向量只使用可合法分发的自制/合成样本；
- 不提交用户私密直播录音；
- 每个测试音频记录采样率、时长、文本、预期事件和许可；
- 情绪测试用例应包含中性说话，避免只测试夸张表演；
- 视觉基线使用本项目角色资产，不使用第三方示例角色；
- 大模型结果允许统计容差，不用单次 exact string 作为唯一标准。

# 4. 资产验收

## 4.1 机器检查

对每个 P0 PNG：

- [ ] 文件存在；
- [ ] 2048×2048；
- [ ] RGBA；
- [ ] alpha 非空；
- [ ] 非全画布不透明；
- [ ] alpha bbox 在画布内；
- [ ] RGB 在 alpha=0 区域不会造成明显 halo；
- [ ] 文件名与 manifest 一致；
- [ ] draw order 唯一且可排序；
- [ ] SHA 和生成记录存在。

## 4.2 合成检查

- [ ] 默认合成能恢复角色；
- [ ] 背景完全透明；
- [ ] 黑底无白边/粉边；
- [ ] 白底无黑边；
- [ ] 棋盘格无透明洞；
- [ ] 额饰链条前后关系正确；
- [ ] 星云披袖金边连续；
- [ ] 手和袖口连接自然；
- [ ] 腰带和星盘位置一致。

## 4.3 变形安全区

用调试器模拟：

- 头 X：±推荐最大值；
- 头 Y：±推荐最大值；
- 头 Z：±推荐最大值；
- 前发各组 impulse；
- 后发各组 impulse；
- 披风最大摆动；
- 左右手姿势切换；
- 眼球最大视线范围。

验收：

- [ ] 不露出粉色背景；
- [ ] 不出现脸部缺口；
- [ ] 刘海根部不离开头顶；
- [ ] 虹膜不越出眼白；
- [ ] 额饰不明显穿过眼睛/脸；
- [ ] 手势切换不出现两只同侧手。

## 4.4 口型对齐

把所有口型叠加/轮播：

- [ ] 中心偏移小于 2–3 px（2048 画布）；
- [ ] 基线一致；
- [ ] 周围脸部不变化；
- [ ] 牙齿、舌头风格一致；
- [ ] REST 与 MBP 可明确区分但不跳位；
- [ ] A/I/U/E/O 视觉可辨；
- [ ] crossfade 不产生双嘴重影。

# 5. 渲染器测试

## 单元/组件

- [ ] `RigAdapter` 可以 mock；
- [ ] 参数 clamp；
- [ ] NaN/Infinity 拒绝；
- [ ] draw order 稳定；
- [ ] 角色卸载释放 WebGL 资源；
- [ ] context loss 恢复；
- [ ] 物理暂停/重置；
- [ ] 30/60 FPS 逻辑一致。

## 截图回归

至少覆盖：

- neutral；
- 闭眼；
- 左/右眨眼；
- A/I/U/E/O；
- happy；
- thoughtful；
- serious；
- surprised；
- tired；
- awakening；
- 左手展示/放下；
- 右手挥手；
- 黑/白/透明背景。

截图比较需要容忍 GPU 小差异，但 alpha 边界和部件位置不能明显变化。

## 性能

在 RTX 4090、目标角色资产下：

- [ ] 60 FPS 模式 p95 frame time ≤ 18.5 ms；
- [ ] 平均 FPS ≥ 58，p95 窗口 FPS ≥ 55；
- [ ] WebGL context loss = 0（正常运行）；
- [ ] 角色静止时不出现持续高 CPU busy loop；
- [ ] 30 分钟内浏览器内存增长不超过基线的约 10–15% 且趋于稳定；
- [ ] 纹理加载后无持续增长。

数值是工程目标，不是宣传性“保证”。每次发布记录实际机器、OBS、浏览器和驱动版本。

# 6. 音频与口型测试

## 6.1 设备和权限

- [ ] 首次拒绝权限时 UI 可恢复；
- [ ] 再次允许后可以启动；
- [ ] 切换设备；
- [ ] 设备拔出后平滑闭嘴；
- [ ] 设备插回后可重选；
- [ ] AudioContext suspended 时有恢复按钮；
- [ ] 浏览器降噪开关状态可读。

## 6.2 wLipSync

固定测试音频：

- 长 A/I/U/E/O；
- `b/p/m` 爆破音；
- `f`；
- 快速普通话句子；
- 低声、正常声、高声；
- 静音和环境噪声。

验收：

- [ ] 长元音主导视素正确且稳定；
- [ ] 静音时自然闭嘴；
- [ ] 噪声不持续开口；
- [ ] 主导视素不会每帧来回翻转；
- [ ] profile 缺失时自动进入音量回退；
- [ ] profile 加载失败有明确原因；
- [ ] 后端关闭时口型继续工作。

## 6.3 延迟测量

### 方法 A：时间戳

- 捕获音频帧时间；
- `lipsync.frame.audioTimestampMs`；
- overlay 实际应用时间；
- 统计 p50/p95/p99。

### 方法 B：视听测试

- 播放/发出短促 `啪`；
- 同时录制麦克风波形和 overlay；
- 逐帧测量声音 onset 与闭唇/开口变化；
- 至少 20 次样本。

目标：

- p50 ≤ 80 ms；
- p95 ≤ 120 ms；
- ASR 辅助高质量模式可放宽到 150–300 ms，但必须在 UI 标注。

# 7. ASR、VAD 与情绪测试

## 7.1 VAD

- [ ] 静音不产生 utterance；
- [ ] 短停顿不错误切断每个词；
- [ ] 长停顿生成 final；
- [ ] 背景音乐默认不持续触发 speech；
- [ ] 麦克风噪声门和后端 VAD 可分别诊断；
- [ ] ring buffer 在会话结束后清理。

## 7.2 ASR

测试中文普通话为主，并至少覆盖：

- 短句；
- 长句；
- 专有名词；
- 数字；
- 轻声；
- 快速说话；
- 中英混合（若启用 auto）。

验收：

- [ ] partial 可以更新且不会重复堆叠；
- [ ] final 正确结束 utterance；
- [ ] 服务超时不会阻塞口型；
- [ ] 模型预热后推理耗时可见；
- [ ] 无 GPU 时有明确降级；
- [ ] 不默认写入文本日志。

不设单一 CER 硬门槛作为发布唯一条件，但每个版本保留固定测试集结果，防止明显回退。

## 7.3 情绪原始输出

测试至少包含：

- 中性解释；
- 自然轻笑；
- 高能量但非生气；
- 低声思考；
- 轻微惊讶；
- 背景噪声；
- 无声。

验收：

- [ ] raw scores 可观察；
- [ ] 无声不触发情绪；
- [ ] 高音量不直接等于 angry；
- [ ] 低置信度不切状态。

## 7.4 情绪状态机

确定性输入序列测试：

- [ ] 阈值进入/退出；
- [ ] neutral bias；
- [ ] 连续确认；
- [ ] hysteresis；
- [ ] minimum hold；
- [ ] cooldown；
- [ ] manual lock；
- [ ] manual release；
- [ ] 后端中断；
- [ ] raw label 快速交替。

目标：

- 中性测试音频中，自动状态切换次数控制在合理范围；
- 不出现 200–400 ms 的短暂情绪闪烁；
- 惊讶等瞬时事件结束后能平滑返回；
- 手动表情优先级始终正确。

# 11. 稳定性与恢复

## 30 分钟 MVP soak

同时开启：

- wLipSync；
- ASR；
- 情绪；
- 60 FPS overlay；
- OBS Browser Source；
- 自动眨眼、头发和披风物理；
- 周期性说话与静音。

检查：

- [ ] 无崩溃；
- [ ] 无 WebGL context loss；
- [ ] 内存趋于稳定；
- [ ] PCM/WS 队列无持续增长；
- [ ] ASR partial 不重复泄漏；
- [ ] 情绪状态机无高频切换；
- [ ] FPS 达标。

## 120 分钟发布候选 soak

在 30 分钟基础上加入：

- 麦克风切换 3 次；
- speech-service 重启 2 次；
- Browser Source 刷新 3 次；
- OBS 场景切换 20 次；
- 自动/手动情绪切换；
- 配置保存与恢复。

# 12. 资源预算

运行时不应同时加载 See-through 资产生成模型。直播模式只加载必要组件。

记录：

- control-web CPU/内存；
- overlay CPU/GPU/纹理；
- speech-service CPU/GPU/VRAM；
- OBS CPU/GPU；
- 总 VRAM。

建议目标：

- speech-service 模型占用稳定；
- 角色渲染纹理不随时间增长；
- 4090 上为 OBS 编码保留充分 GPU 余量；
- 若 GPU 使用冲突，允许 speech-service CPU/轻量模式或降低模型频率。

# 13. 发布阻断项

出现以下任一情况不得发布：

- 运行时资产含粉色背景；
- overlay 不能透明；
- 后端故障导致口型完全失效且无降级；
- 情绪每秒切换；
- 麦克风断开后角色持续张嘴；
- 配置会覆盖/丢失用户资产；
- 模型权重或第三方许可证不明；
- 默认保存录音或上传音频；
- 30 分钟测试内存持续线性增长；
- OBS 中控制 UI 可见；
- 密码/token 出现在日志或导出配置。
